# P0.1 — Dynamic LOT Category Characteristics

Physical RC10.2 validation exposed a blocking seller-flow defect: mobile «Создать ЛОТ» reached preview without collecting required ProductType characteristics, then backend rejected publish with messages like «Заполните обязательную характеристику «Мощность»».

## Root cause

1. **Characteristics belong to ProductType**, not Category directly (`ProductCharacteristicDefinition.productTypeId`).
2. Web seller flow already loads schema via `GET /api/taxonomy/browse?productTypeId=…` and renders `DynamicCharacteristicsFields`.
3. **Mobile always sent `characteristics: []`** and had no UI to collect values.
4. Backend correctly enforces `canPublishActive()` on ACTIVE publish (`CHARACTERISTICS_REQUIRED`).

### Taxonomy audit (physical cases)

| Case | Verdict |
|------|---------|
| Электроинструмент → Дрели → **Мощность** (Вт) | **Legitimate** — required NUMBER on drill ProductType |
| Автоаксессуары → Автомобильные компрессоры → **Производительность** (л/мин) | **Legitimate** for compressors — air flow rate, not a mapping defect |
| Автоаксессуары → Держатели для телефона | **No required characteristics** — physical error likely from wrong ProductType selection or missing UI |
| Одежда → Платья → **Размер** required | Legitimate |

**Conclusion:** No taxonomy seed fix required. The defect is missing mobile schema-driven form + pre-preview validation.

## API contract

Canonical schema (reuse + mobile wrapper):

```http
GET /api/mobile/seller/product-types/:productTypeId/characteristics
```

Response:

```json
{
  "productTypeId": "…",
  "categoryId": "…",
  "name": "Дрели",
  "characteristics": [
    {
      "id": "…",
      "name": "Мощность",
      "slug": "power",
      "type": "NUMBER",
      "required": true,
      "unit": "Вт",
      "options": null,
      "sortOrder": 0,
      "filterable": true
    }
  ]
}
```

Fallback: `GET /api/taxonomy/browse?productTypeId=…` (same shape).

Publish payload uses stable `definitionId` values:

```json
"characteristics": [
  { "definitionId": "…", "valueNumber": 800 }
]
```

## Mobile UX

- After ProductType selection, show **Характеристики** section.
- Required fields block preview with human copy («Укажите мощность», «Выберите размер»).
- Optional fields behind **Добавить характеристики**.
- Category/ProductType change prunes stale values.
- Server `CHARACTERISTICS_REQUIRED` returns seller to details, preserves draft, highlights fields.
