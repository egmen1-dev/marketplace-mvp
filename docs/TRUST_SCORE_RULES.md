# Trust Score Rules (MARKETPLACE-TRUST-SCORE-MODEL-001)

Прозрачная внутренняя модель расчёта **Рейтинга доверия** продавца (0–100) и **Доверия к товару**.

Флаг: `MARKETPLACE_TRUST_SCORE_MODEL_ENABLED=true`

Trust Score **не влияет** на search ranking, catalog ranking, orders lifecycle, finance ledger и Stripe.

---

## Seller Trust Score

**Название для пользователя:** Рейтинг доверия

**Стартовый рейтинг нового продавца:** `70/100`

Причина: аккаунт создан, базовые данные проверены, история отсутствует. Нет бонуса за отсутствие истории и нет штрафа за отсутствие продаж.

### Факторы модели `SellerTrustScore`

| Фактор | Вес |
|--------|-----|
| Качество товаров | 20 |
| Выполнение заказов | 25 |
| Скорость отправки | 20 |
| Отзывы покупателей | 20 |
| Активность продавца | 10 |
| Проверка аккаунта | 5 |

Каждый фактор оценивается в диапазоне 0–100, итог — взвешенное среднее.

---

## Таблица влияния действий

### Заказы — быстрая отправка

| Отправка | Изменение |
|----------|-----------|
| до 24 часов | +0.5 |
| 24–48 часов | 0 |
| 3–4 дня | −2 |
| более 5 дней | −5 |

### Отмена заказа продавцом

| Ситуация | Изменение |
|----------|-----------|
| по вине продавца | −5 |
| повторные отмены | −10 |

### Выполнение заказа

| Ситуация | Изменение |
|----------|-----------|
| успешная доставка | +0.2 |
| проблемный заказ | −3 |

### Отзывы

| Оценка | Изменение |
|--------|-----------|
| 5★ | +0.5 |
| 4★ | +0.2 |
| 3★ | 0 |
| 2★ | −1 |
| 1★ | −2 |
| фото в отзыве | дополнительно +0.2 |

### Качество карточки

| Состояние | Изменение |
|-----------|-----------|
| полная галерея | +5 |
| нет главного фото | −10 |
| характеристики заполнены | +3 |
| характеристики пустые | −5 |
| полное описание | +2 |
| описание отсутствует | −3 |

### Проверка аккаунта

| Действие | Изменение |
|----------|-----------|
| подтверждение телефона | +2 |
| подтверждение реквизитов | +3 |

---

## Ограничение изменений

| Лимит | Значение |
|-------|----------|
| за день | ±10 баллов |
| за одно событие | ±5 баллов |

---

## Период обновления

- после каждого значимого события;
- плановый пересчёт (`DAILY_RECALC`) при агрегации репутации.

### События

- `ORDER_CREATED`
- `ORDER_SHIPPED`
- `ORDER_DELIVERED`
- `ORDER_CANCELLED`
- `REVIEW_CREATED`
- `PRODUCT_UPDATED`
- `ACCOUNT_VERIFIED`
- `DAILY_RECALC`

---

## История изменений (`TrustScoreHistory`)

Поля: `id`, `sellerId`, `oldScore`, `newScore`, `reason`, `eventType`, `createdAt`

Пример:

```
Ваш рейтинг изменился: 92 → 89
Причина: Заказ №123 был отправлен через 4 дня
Изменение: −3 балла
```

## Уровни доверия (покупатель)

| Диапазон | Уровень |
|----------|---------|
| 90–100 | Высокий уровень доверия |
| 70–89 | Хороший уровень доверия |
| 50–69 | Есть что улучшить |
| 0–49 | Низкий уровень доверия |

## UI

- Продавец: `/account/reputation` — рейтинг, что помогает / снижает, следующее улучшение, история
- Покупатель: PDP — рейтинг продавца, уровень, причины доверия
- Вместо «Проверен» показывается «Данные продавца подтверждены» с перечислением проверок
